## מה הושג בגרסה זו

### פעולה 3 חלק א' — Width Caching
- **`_linesCache`** (Map, max 2000) — מטמון תוצאות `getLinesFromParagraph` לפי hash של טקסט + רוחב + סגנון.
- מאיץ עימוד פי 3-5 על ידי מניעת חישובים חוזרים של אותה פסקה.
- מתאפס בכל קריאה ל-`typesetDocument`.

### פעולה 3 חלק ב' — Canvas API
- **`measureWordWidth(word, styleObj)`** — רוחב מילה בודדת עם מטמון, fallback ל-DOM.
- **`measureLineWidthCanvas(text, styleObj)`** — רוחב שורה, fallback ל-DOM.
- **`estimateLineCountCanvas(words, colWidth, styleObj, opts)`** — אומדן גרידי של מספר שורות.
- **`_wordWidthCache`** (Map, max 8000) — מטמון רוחבי מילים.
- **`_spaceWidthCache`** (Map) — מטמון רוחב רווח לכל גופן.
- **דיוק**: סטייה ממוצעת 0.25px מול DOM, מקסימלית 0.47px.
- מונע Layout Thrashing — אין Reflow בדפדפן.

### פעולה 4 — Knuth-Plass מלא

#### האלגוריתם
- **`knuthPlassBreak(words, colWidth, styleObj, opts)`** — תכנון דינמי על גרף נקודות שבירה.
- **מודל אובייקטים** (לפי מחקר): תיבות (מילים), דבק (רווחים עם stretch/shrink), קנסות.
- **נוסחאות TeX**: `badness = 100*|ratio|³`, `demerits = linePenalty + badness² + penalty²`.
- **Prefix sums** לחישוב O(1) של רוחב שורה.
- **Active nodes pruning** — O(N²) במקום O(N³).
- **מטמון נפרד** `_kpCache` (max 1500).

#### פרמטרים מתקדמים (לפי מחקרים)
- **`looseness`** — מאפשר הוספת/הסרת שורות מהאופטימום הטבעי (+1 = שורה יותר, -1 = פחות).
  - מימוש מלא: `bestByLineCount[end] = Map<lineCount, node>` — שומר נקודות לפי מספר שורות.
  - אופטימיזציה: מסלול מהיר (DP פשוט) כש-`looseness=0`, מסלול מלא רק כש-`looseness!=0`.
- **`adjdemerits`** (ברירת מחדל 3000) — קנס על מעבר בין קטגוריות כושר בלתי-תואמות.
  - 4 קטגוריות: tight(0) / decent(1) / loose(2) / very-loose(3).
  - קנס כש-`|prevFitness - currFitness| > 1`.
- **`parfillskip`** (ברירת מחדל true) — שורה אחרונה עם `badness=0` תמיד (כמו `\parfillskip` ב-TeX).
- **`clubpenalties`** (מערך) — קנסות לשורות ראשונות של פסקה אחרי כותרת.
  - דוגמה: `[10000, 10000, 150]` — אוסר שבירה אחרי שורה 1 ו-2.
  - `lineCost` מקבל `lineNumInPara` ומחיל את הקנס המתאים.

#### אינטגרציה ב-renderer — הפתרון הקריטי
**הבעיה**: KP חישב שורות אופטימליות, אבל ה-renderer עשה `item.lines.join(' ')` והדפדפן שבר שורות מחדש — מה שביטל לחלוטין את עבודת KP.

**הפתרון** — שני שלבים:
1. **במהלך העימוד** (`performTypesetInner` + `balanceColumns`): `_kpBrEnabled = false` — הדפדפן שובר שורות בעצמו (מהיר, ללא קריסה).
2. **אחרי העימוד** (`applyKpLineBreaks`): מחיל `<br>` על כל הפסקאות ש-KP חישב — KP שולט בשבירת השורות הסופית.

**סימון `_fromKp`**: מבדיל בין שורות מ-KP (מקבלות `<br>`) לשורות מ-DOM probe ישן (מקבלות `join(' ')`).

**4 מסלולי רינדור** תוקנו:
1. `applyCandidateLayoutToDOM` (V2)
2. `balanceColumns` (V1) — `renderSingleItemFast` + פיצול טורים
3. מסלול טור יחיד — `performTypesetInner`
4. מסלול דו-טורי — `performTypesetInner`

### אופטימיזציית ביצועים — מניעת קריסת דפדפן

**הבעיה**: המימוש המלא של `looseness` עם `bestByLineCount` גרם לצריכת זיכרון גבוהה וקריסת הדפדפן בטקסט מלא (1.5M תווים).

**הפתרון** — 3 רמות אופטימיזציה:
1. **מסלול מהיר** — DP פשוט (נקודה אחת לכל `end`) כש-`looseness=0` (ברירת מחדל).
2. **מסלול מלא** — `bestByLineCount` רק כש-`looseness!=0`, עם הגבלת טווח lineCount (±3).
3. **`_kpBrEnabled` דגל** — `<br>` מוחל רק ב-`applyKpLineBreaks()` (פוסט-פרוססינג), לא במהלך probe renders של `balanceColumns`.

## נקודות קריטיות לזכור

### בעיות שתוקנו ואסור להחזיר

1. **`rect.width` ב-RTL** — אינו מייצג רוחב שורה. השתמש ב-`rect.right - colRect.left`.
2. **`item.lines.join(' ')`** — מבטל את עבודת KP. השתמש ב-`<br>` (עם `_kpBrEnabled`).
3. **`bestByLineCount` במהלך עימוד** — גורם לקריסת זיכרון. השתמש במסלול מהיר (DP פשוט) כברירת מחדל.
4. **`<br>` ב-probe renders** — גורם לקריסת זיכרון. החל רק ב-`applyKpLineBreaks()`.
5. **U+E000 בהערות שוליים** — חייב ניקוי לפני הצגה.
6. **`detectTofu` ישן** — תמיד החזיר false. חייב השוואה ל-serif גנרי.
7. **סף H3 = 190px** — גורם לעמודים קצרים. השתמש ב-120px.

### בעיות פתוחות

1. **אי-איזון אחרי `applyKpLineBreaks`** — `<br>` משנה גבהי פסקאות אחרי איזון הטורים. **פתרון עתידי**: הרצת איזון טורים נוספת אחרי `applyKpLineBreaks`, או שימוש ב-`numLines` של KP לחישוב גובה ללא DOM.
2. **`looseness` לאיזון טורים** — מנוטרל זמנית עקב בעיית ביצועים. יש להפעיל רק פעם אחת לכל בלוק, ולא בתוך לולאת איזון.
3. **`clubpenalties` לא מופעל** — המנגנון קיים אבל לא מועבר מ-`getLinesFromParagraph`. יש להעביר כאשר פסקה באה אחרי כותרת.

### עקרונות עיצוב

1. **KP שולט בשבירת שורות** — ה-renderer חייב לכבד את השורות ש-KP חישב.
2. **הפרדת עימוד ורינדור** — `_kpBrEnabled = false` במהלך עימוד, `true` בפוסט-פרוססינג.
3. **מסלול מהיר כברירת מחדל** — `looseness=0` → DP פשוט, `looseness≠0` → DP מלא.
4. **מטמון נפרד** — `_linesCache` (תוצאות), `_wordWidthCache` (רוחבי מילים), `_kpCache` (KP).
5. **RTL-aware** — כל מדידות הרוחב משתמשות ב-`rect.right - colRect.left`.

## הצעדים הבאים המומלצים

1. **איזון טורים אחרי `applyKpLineBreaks`** — הרצת איזון נוספת אחרי החלת `<br>`, כדי לתקן את האי-איזון (617 → מטרה <10).

2. **`looseness` לאיזון טורים** — הפעלת `looseness=-1` על הפסקה האחרונה בטור הארוך, אבל **רק פעם אחת לכל בלוק** (לא בתוך לולאת איזון).

3. **`clubpenalties` לכותרות** — העברת `clubpenalties: [10000, 10000, 150]` כאשר פסקה באה אחרי כותרת, כדי להבטיח "שתי שורות אחרי כותרת".

4. **מדידת גובה ללא DOM** — שימוש ב-`numLines` של KP וב-`lineHeight` לחישוב גובה פסקה ללא צורך ב-DOM probe. יאפשר איזון טורים מדויק יותר.

5. **היפנציה עברית** — מחקר 2 ממליץ על `hyphenpenalty=10000` (איסור היפנציה בעברית). כרגע אין היפנציה, אבל כדאי לוודא שהקנס מופעל.

6. **מעבר ל-`balanceColumnsV2`** — המנוע החדש (מבוסס מועמדים) יכול לנצל את KP טוב יותר. כרגע מנוטרל (`__useBalanceV2 = false`).

7. **בדיקת דלילות אחרי `applyKpLineBreaks`** — הרצת `tightenRunts` נוספת אחרי החלת `<br>`, כדי לטפל בשורות דלילות שנוצרו.
